### 1.Function Calling

1. 这节讲什么？
   
   ```
   Function Calling 是让大模型把自然语言意图转换成结构化函数调用请求的机制。
   模型先理解用户意图，然后判断要不要调用工具，再生成函数名和参数。
   ```

2. Function Calling 为什么重要？
   
   ```
   它重要是因为 Agent 想要执行外部动作，比如查数据库、调用 API、检索文档，
   就不能只靠模型生成文本，而要通过工具调用完成。
   ```

3. 它是怎么训练出来的？
   
   ```
   Function Calling 能力主要来自模型训练和对齐：
   预训练让模型具备语言、代码和结构化输出能力；
   SFT 用标注样本教模型如何选择函数和填写参数；
   RLHF 让模型的调用行为更符合人类偏好。
   ```

4. 工具调用为什么会失败？
   
   ```
   工具调用失败常见原因包括：
   函数职责不清、参数太多、缺少必要参数、
   参数描述不清、JSON Schema 太复杂、
   缺少校验和重试机制。
   ```

5. 面试如果问“工具调用失败怎么优化”，我会怎么答？
   
   我会先判断失败发生在哪一层。
   
   如果是模型选错工具，说明函数名、描述或工具边界不清楚，需要让工具职责更单一，命名更明确。
   
   如果是参数生成错误，通常要减少参数数量，避免复杂嵌套，并在 JSON Schema 里写清字段类型、是否必填和参数含义。
   
   如果是执行阶段失败，还需要加入参数校验、错误反馈和重试机制，让模型根据失败原因重新生成调用参数。

### 2.Agent评测vs传统测试

1. 这节讲什么？
   
   主要讲 Agent 评测和传统软件测试的区别，以及 Agent 评测为什么更难。

2. 为什么 Agent 不能用传统测试那套方法直接评估？
   
   传统软件通常是确定性的，同样输入应该得到同样输出，可以用 assert 判断对错。
   但 Agent 是概率性的，同一个输入多次运行可能产生不同结果，而且任务往往是开放式的，不一定只有唯一标准答案。
   同时 Agent 的执行过程更复杂，包含规划、工具调用、观察、再规划等步骤，所以不能只看最终输出。

3. Agent 评测和传统测试有什么不同？
   
   - 确定性不同：传统测试输出稳定，Agent 输出可能变化。
   - 任务性质不同：传统测试多是封闭任务，Agent 多是开放任务。
   - 判断方式不同：传统测试可以判断对错，Agent 往往要打分或比较好坏。
   - 评测对象不同：传统测试看函数返回值，Agent 要看完整轨迹。
   - 失败形态不同：传统软件多是异常或返回错误，Agent 可能是选错工具、参数错、目标跑偏、幻觉、自以为完成等。

4. 面试如果问“Agent 系统应该怎么测试/评估”，我会怎么答？
   
   Agent 系统不能完全照搬传统软件测试，因为它不是确定性的函数调用，而是一个带有规划、工具调用和反馈修正的决策过程。同样输入多次运行，路径和结果都可能不同，所以不能只用 assert 判断最终输出。  
   我会从生命周期角度评估：开发前定义成功标准，开发中分别评测 Prompt、RAG、工具调用和规划能力，上线前用测试集、仿真环境、压测和红队测试做验证，上线后通过日志、trace、metrics 和用户反馈持续监控任务成功率、失败率、延迟、成本和安全问题。

### 

Agent 评测不是只看最终答案，而是沿着生命周期评估：开发前定标准，开发中测组件，上线前测完整链路，上线后看真实反馈。

- 开发前：
  
  - 定义成功标准。比如任务完成率、工具调用准确率、回答质量、延迟、成本和安全边界等等
  
  - 模型选型。比较不同模型在目标场景下的效果、成本、延迟和稳定性等

- 开发中：
  
  - 对agent的关键组件分别进行测评。包括 Prompt、RAG 检索质量、工具选择、参数生成、规划能力、多轮对话状态管理等。
  
  - 同时观察中间轨迹是否合理，比如是否选对工具、参数是否正确、是否能根据工具结果继续规划

- 上线前：
  
  - 做端到端测评。验证完整任务链路是否稳定完成。
  
  - 进行小规模用户测试、仿真测试、安全测试等，并建立自动化评测pipeline

- 上线后：
  
  - 基于真实流量持续监控，包括任务成功率、失败率、工具调用错误率等等。
  
  - 发现问题后回流到测试集和评测 pipeline 中，持续迭代。
