## 常见的向量数据库

常见的向量数据库有Milvus，Weaviate，Chroma，Qdrant。具体来讲：

Milvus建立在Faiss、Annoy等开源向量搜素库的基础上，能够支持数十亿级别甚至万亿级别的向量搜素库，并且检索速度快，万亿向量数据集上检索速度的延迟可以控制在毫秒级别。

除此以外，Milvus还支持数据分片，数据持久化，流式数据摄取，混合搜索等很多高级功能。具有可高用性、高性能和易扩展的特点，用户还可以将其部署在Kubernetes上面。并且可靠性强，具有数据复制和故障恢复的功能。

Weaviate具有鲁棒性，云原生性和可扩展性的特点。它结合了向量搜索和结构化过滤的能力，同时拥有云原生数据库的容错性和可伸缩性。在百万级的向量数据上，可以实现毫秒级的检索。它可以方便调用OpenAI，Cohere以及Hugging Face平台提供的先进的数据向量化接口和模型。缺点是目前只支持HNSW这一种检索算法。

Chroma是一款AI原生的开源向量数据库，主要功能和特点围绕AI应用开发而设计。主要针对大模型RAG场景，目前只实现了单机方案。相比Weaviate和Milvus，Chroma更轻量化。检索上实现了FAISS索引，不支持GPU加速。

## RAG与大模型应用

RAG最直观的应用便是问答场景。

大模型的知识来源于预训练阶段，通过大量的无监督数据，利用下一个词预测任务来完成训练。

大模型的“无监督训练”，本质上是“自己给自己造标签”。监督信号来自数据本身。被称为Self-surpervised learning 自监督学习。

大模型预训练通过自监督方式，把原始文本自动构造成“上下文—目标词”对，以预测下一个词或被遮盖词作为学习目标，从而在无需人工标注的情况下学习语言结构与隐含知识。

举个例子：原始文本是”今天 天气 真 不错“。

大模型的任务就是：根据前面的词预测下一个词。

所以就可以根据训练数据自己构建样本了。

| 输入    | 标签  |
| ----- | --- |
| 今天    | 天气  |
| 今天天气  | 真   |
| 今天天气真 | 不错  |

GPT / BERT 属于自监督学习，不是纯无监督。有明确目标，有loss，有标签，只是标签是数据自动生成的。

RAG工作流程的三个主要阶段：数据准备、数据召回和答案生成。这个看似和上一篇帖子当中的描述不同，实际上RAG的工作流程都是相似的，只是大家的命名和分类有些差异。由于大模型是冻结的，所以输出质量取决于数据质量和检索策略。

数据准备阶段通常包括：识别数据源、从数据源中提取数据、清洗数据并将其村春再数据库中等环节。

向量数据库大概分为三种类型：向量存储库、搜索引擎和图数据库。

向量存储库非常适合存储文本、图像、音频等非结构化数据，并根据语义相似性搜索数据。

搜索引擎，在RAG系统中，可以从通用搜索引擎如百度、Bing等或者内部搜索引擎中检索数据。

图数据库：图数据库以节点和边的形式存储数据。它适用于存储结构化数据，如表格、文档等，并使用数据之间的关系搜索数据。

数据召回

数据召回部分的主要任务是从大型文本数据库中检索与输入相关的信息。 

答案生成

输出的质量取决于数据的质量和检索策略，同时生成输出的指令也会极大地影响输出的质量。在RAG场景下，幻觉主要体现在跳脱知识片段回答问题上，即回答的答案并不出现在增强的知识片段中。

**RAG的优点：**

1.高质量的答案生成，降低答案生成的幻觉。

2.可扩展性。由于RAG采用了检索--生成的框架，因此只需要更新检索部分的数据，就可以使模型适应新的知识领域。

3.模型可解释性。可以很容易的追溯模型是从哪些文档中提取信息的，并且可以评估模型的回答是否是基于可靠的数据来源。

4.成本效益。RAG的知识库可以和生成模型解耦，因此有一定的数据量，很多企业就可以用RAG作为微调的替代方法。

**RAG的缺点：**

1.依赖于检索模块。RAG系统给出的答案极其依赖于检索的质量。如果检索到的文档与问题无关或者质量较低，生成的回答也可能质量较低。如果检索的文档并未覆盖到问题的答案，那模型也基本无法回答用户提出的问题。因此需要我们使用很多策略来提高文档片段的召回率。

2.依赖于现有的知识库。

3.推理耗时。RAG系统需要先检索文档，然后生成答案，相比于纯粹的大模型推理，整个系统的推理耗时会更长。

4.上下文窗口限制。召回模块输出的文档片段数量需要考虑到生成模型能处理的最大长度。可以对生成的模型应用长度外推技巧。

**RAG的使用场景**

1.文档问答。

2.图谱问答。知识图谱是一种以三元组形式存储各种知识的结构化表示方法。

3.工具召回。在智能代理agent应用中，RAG系统可以根据用户的问题从预先配置好的工具列表中检索出对问题回复有帮助的工具，然后模型会判断是否调用某个工具生成一个观察结果来确定最终的答案。

4.示例召回。

文档问答再“找文本”，而图谱问答在“查事实结构”

文档文档本质是从非结构化文本中检索相关片段，再让LLM生成答案。

数据形态有pdf、word、网页、markdown、说明书等等，本质都是自然语言锻炼。

图谱问答本质是在结构化知识网络上做查询与推理。不是找“一段话”而是在查找关系。

数据形态是三元组，例如（实体1，关系，实体2）

示例召回本质是给模型找参考案例。召回的是历史回答、代码样例、任务样例、思路模板等等。不是事实也不是能力，而是参考的范式。

工具召回本质是给模型找可执行能力。召回的是可调用函数 / API / 外部系统能力。

在OpenAI发布的“Scaling Laws for Neural Language Models”中提到，伸缩法则（Scaling Law）是指随着模型的大小、数据集的大小以及用于训练的计算量的增加，模型的性能会提升。在RAG当中，除了以上的三点，还需要考虑知识库的大小。

在推理任务上，大多数RAG经典模型不能生成正确答案。

在实际应用中，一方面我们会尽可能地考虑如何优化RAG系统的召回部分。另一方面，还需要考虑如何让大模型有选择地利用检索到的知识，而非盲目地生成答案，

在RAG系统中，系统的偏好分为内容风格偏好和选择性使用检索知识的知识偏好。
