### 实战



- **0%–70% 的时间，压在 RAG 上**  
  不是“写一个 demo 就完事”，而是反复做三件事：  
  1）不同 chunk 策略对召回的影响  
  2）dense / sparse / hybrid 检索的 trade-off  
  3）用 PR-AUC、Recall@k 去解释“为什么这个方案更好”  
  你要训练的是：**能用指标讲清楚系统设计选择的能力**。

- **20% 的时间，用在 Agent，但只当“表达层”**  
  Agent 在你这里不是研究对象，而是一个**把 RAG 能力包装成“像样应用”的方式**。  
  你需要做到的是：
  
  - 会设计 Agent 的职责边界
  
  - 会用 Function Call / Workflow
  
  - 会用 LangGraph 或 Dify 快速落地  
    但**坚决不要在框架 API、协议细节上耗时间**。那是平台工程师的赛道，不是你现在的。

- **10%–15% 的时间，用来补“LLM 特有的模型理解”**  
  不是再学一遍 Transformer，而是只关注这些问题：
  
  - 自回归生成的误差累积
  
  - 长上下文与 Attention 复杂度
  
  - KV Cache、推理阶段瓶颈  
    目的是：**让你在讨论系统性能或模型行为时，不显得“只会调 API”**。

- **SFT / DPO / RLHF / 量化 / 推理优化，全部放在“理解优先，实战靠后”的位置**
