### MCP

- MCP 是什么？
  - MCP是一套标准协议，让LLM应用能用统一方式连接外部工具、数据和提示词。
- Host、Client、Server 分别做什么？
  - Host：运行LLM的应用
  - Client： Host里面的连接器，负责按MCP协议和外部服务沟通
  - Server：提供能力的一方。
- MCP 为什么比“每个工具各接一次”更方便？
  - MCP解决的根本问题是：以前每接一个工具，应用都可能要单独对接一套格式。有了MCP，工具服务按统一协议暴露能力，Host可以连接多个Server，也可以发现其提供的工具、资源和提示词。

MCP采用的是客户端-服务端架构。Host通常会为每个连接的MCP Server建立一个Client，因此它能同时接入多个不同能力的Server。

###### 1.MCP与Function Calling的区别

Function Calling解决“模型怎样提出调用某个函数”

MCP解决“LLM应用怎样用统一方式连接和管理外部能力”

- MCP 和 Function Calling 的核心区别是什么？
  - Function Calling 是模型生成结构化函数调用的能力，通常工具列表由应用在当前会话中预先提供；MCP 是 LLM 应用连接外部工具、资源和提示词的标准协议，采用 Host-Client-Server 架构，支持多个 Server 接入和能力发现。前者更关注“怎么发起一次工具调用”，后者更关注“怎么标准化地连接、发现和管理外部能力”。
- 为什么说 MCP 的工具发现能力比传统 Function Calling 更动态？
  - Function Calling在会话上下文静态配置可用工具列表
  - MCP支持工具能力的动态发现和查询机制
- 两者是互相替代，还是可以配合使用？
  - 两者可以配合使用。MCP Server 把工具能力提供给 Host；Host 再把这些工具描述交给模型，模型可通过 Function Calling 选择并调用工具。



MCP 统一了 Host 与 Server 的连接、能力发现和消息格式。Host 可以按协议询问 Server 有哪些工具、每个工具需要哪些参数，再统一调用；不必为不同 Server 各写一套私有接入方式。

MCP 提供标准化的工具描述和通信协议；模型依据工具的参数 Schema 生成输入，Host 通过统一协议调用 Server。

多个 Server 有各自的 Client；“统一”指的是它们遵守同一套 MCP 协议，Host 可以用统一方式管理和调用，而不是所有 Server 共用同一个 Client。

**底层连接上**：Host 通常为每个 MCP Server 建立各自的 Client 或会话连接。

Host
├─ Client A <-> 文档检索 Server
├─ Client B <-> 库存查询 Server
└─ Client C <-> 日志读取 Server

**Host 对模型提供能力时**：Host 会把这些 Client 收集到的工具，整理成一个统一的可用工具集合。

模型看到：
search_manual
query_inventory
read_device_log



###### 2. MCP（Model Context Protocol）

- MCP 解决什么接入问题？
  - 大模型本身只能进行问答，模型是否会调用工具，取决于模型的Function Calling或者Agent能力。MCP负责把外部工具、资源、提示词按统一协议提供给应用使用。
- Host、Client、Server 如何协作？
- MCP 与 Function Calling 如何配合？
- 本地和远端 MCP Server 的适用场景怎么解释？

MCP Server和Tool

MCP Server和传统的云端服务器等不是同一个概念，MCP Server只是一个程序，该程序要符合MCP协议。没有强制联网的要求。Tool指的就是MCP里面的函数。

`MCP Tool` 可以理解为“暴露给模型的可调用能力”，通常由一个函数实现，但底层也可以是 API、数据库查询或业务流程，不限于普通函数。

MCP协议并没有整合了各家大模型不同的function call 的标准，整合成了一个统一的标准协议。

MCP 统一的是 **Host 与 MCP Server 的协议**；Host 仍需要把 MCP 工具描述适配成当前模型厂商所需的工具调用格式。



###### 3.MCP核心能力交互

1.每个MCP Server的函数列表

2.每个函数的调用方法

即函数的注册与使用。

MCP协议并没有规定如何与模型进行交互。

MCP 协议不规定模型内部如何推理，也不规定模型本身怎样对话。它主要规定：**如何连接、发现工具、读取资源、调用能力并返回结果。**

本质上是LLM黑盒模型，在不训练模型、不改变模型权重的前提下，大家没有办法对LLM的的步骤做功夫。**只能对输入和输出做功夫了。**

不改模型权重时，如何通过模型的输入、输出和外部交互让它完成复杂任务。

**Agent本质：** 在基础模型固定时，Agent 是围绕大模型输入、输出与外部环境构建的运行程序。它通过向模型提供上下文、工具描述和状态信息，接收模型生成的回答或工具调用，再把工具执行结果重新输入模型，形成多轮闭环。

**MCP本质：** 通过标准化协议，使 Host 能够以统一方式发现、描述和调用外部工具、资源及提示词，并将调用结果返回给模型；它规范的是模型应用与外部能力之间的输入输出交互。

**RAG本质：** 通过检索外部知识，将与当前问题相关的文本补充到模型上下文中，主要增强模型输入的信息量、时效性和事实依据。

**Skill本质** ，将领域规则、任务流程、最佳实践和相关资源组织为可复用、可按需加载的指导材料，主要增强模型对“任务应如何完成”的理解。把这些放在模型的输入当中

RAG 和 Skill 主要向模型补充输入上下文；

MCP 不仅提供工具描述等输入，还标准化处理模型发出的工具调用请求，并将外部执行结果以统一格式回填给模型，形成“模型输出行动、环境返回观察、模型继续决策”的闭环。

真正决定怎样解析模型输出、是否重试、是否校验或拦截高风险操作的，通常是 Host/Agent 程序；MCP 提供的是它与 Server 交互的标准协议。



###### 4. MCP Host与模型沟通

MCP Host如何与模型进行沟通，即学习如何能够与模型持续交互的协议

SSE连接：浏览器只发送一次请求，模型接收请求后不断的返回新的信息，返回结束后发送结束信息，连接中断。**Client 建立到 Server 的事件流连接后，Server 可以持续向 Client 推送事件的一种传输方式。**
