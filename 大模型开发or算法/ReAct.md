###### 1.ReAct

ReAct=Reasoning+Acting

Reason -> Act -> Observation -> Reason -> ... -> Final Answer

Reason:根据当前任务、历史上下文和上一步结果，判断下一步做什么

Act：模型决定调用某个工具，并生成工具名和参数

Observation：外部框架真正执行工具后，把真实结果返回给模型

Agent = LLM 模型 + Harness

Harness是包在大模型外面的Agent运行与控制程序。Harness负责执行工具并控制循环。

**谁复杂什么**

| 部分              | 负责内容                                 |
| --------------- | ------------------------------------ |
| 模型              | 判断下一步、选择工具、生成参数、根据结果决定继续还是结束         |
| Harness/Agent框架 | 调用模型、解析tool call、执行工具、回填结果、维护状态和控制循环 |
| 工具/外部环境         | 返回真实信息或执行真实动作                        |

真正执行、校验、重试、停止，都是 Harness 的工作。

模型负责提出下一步；Harness 负责让这一步安全、可执行、可停止。

###### 2.如何判断Agent陷入无效循环

- 相同或相似的工具名与参数是否连续出现

- 连续几步是否没有新增事实、代码修改、测试结果或任务进展

- 是否反复出现同一错误

- 是否接近最大步数、时间、Token或者成本预算

###### 3.发现无效循环后怎样处理

处理顺序为：检测->修正->停止

修正不是盲目重试，而是根据错误提示给模型新的、可行动的信息：

- 短暂网络错误：允许有限次数重试

- 参数错误：把具体错误返回给模型，让它改参数

- 查询没有结果：尝试改写查询、换工具或扩大条件

- 当前路径不通：让模型基于已有Observation重新规划

- 缺少用户才能决定的信息：发起澄清提问。

- 如果超过了重试、步数、时间或成本上限，Harness必须停止。

###### 4.澄清提问与高风险确认

澄清提问是为了补全完成任务所必须的信息

高风险确认是为了保留用户控制权。

模型负责决策；工具提供真实反馈；Harness 负责状态、校验、预算、循环修复和停止，使多步执行变得可控。

###### 5.Harness 为什么不能只靠 Prompt 来防止 Agent 无限循环？

Prompt 可以把错误、Observation 和行为规则提供给模型，帮助模型自我修正；但模型仍可能忽略规则、误判进展或继续生成调用。Harness 位于模型与工具之间，负责记录状态、检测重复、限制预算、校验权限，并在达到停止条件时拒绝继续执行，因此不能只依赖 Prompt 防止无限循环。

Prompt能做的是“劝模型”：

- 根据错误修改参数

- 换查询、换工具、重新规划

- 信息不足时向用户提问

- 提醒它不要重复调用

Prompt不能可靠的“强制执行”：

- 统计连续重复调用次数

- 判断是否超过Token、时间、费用和步数预算

- 阻止下一次工具真正执行

- 在模型判断错误时强制停止

- 保证高风险操作经过用户同意。
